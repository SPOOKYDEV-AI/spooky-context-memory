# Pattern Memory

Patterns prevent thousands of near-duplicate capsules from becoming thousands of independent rules.

## Two memory levels

```text
Experience capsule
→ one accepted/rejected trajectory in one context

Experience pattern
→ a recurring causal mechanism across contexts
```

A pattern signature compares:

- reasoning failures;
- triggering signals;
- lost or required constraints;
- predicted consequences;
- resolution principles;
- scope keys.

Scope has a low matching weight so the same mechanism can be recognized across different projects. Scope still controls whether a concrete solution is applicable.

## Pattern relationships

A new experience may be classified as:

- duplicate;
- instance of an existing pattern;
- extension;
- narrowing;
- contradiction;
- new pattern.

## Independent support

Repeated events in the same test run or copied workflow are not independent proof. Pattern support tracks distinct projects, workflows, environments, supporting capsules, and counterexamples.

Typical lifecycle:

```text
1 context  → hypothesis
2 episodes → candidate
3 episodes across at least 2 independent contexts → active
```

These thresholds are conservative defaults, not universal scientific guarantees.

## Prevention, not universal fixes

A pattern should tell the agent:

- what reasoning failure is probable;
- what signals triggered it previously;
- what must be preserved;
- what shortcut to avoid;
- what to verify.

The local capsule still owns the context-specific implementation details.
