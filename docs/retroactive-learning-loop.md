# Retroactive Learning Loop

## Purpose

A View outcome must change future memory behavior. Otherwise the system only searches repeatedly without learning how to search better.

```text
attention
→ Views
→ triage
→ action or prediction
→ observed result
→ qualified verdict
→ attention feedback
→ link plasticity
→ capsule refinement
→ future View regeneration
```

## Qualified View verdicts

A View can be:

- supported;
- partially supported;
- contradicted;
- mismatched to context;
- mismatched to scope;
- in conflict with truth anchors;
- missing evidence;
- superseded;
- redundant;
- unresolved.

These verdicts produce different updates. A context mismatch should add applicability discriminators. Missing evidence should preserve or reactivate uncertainty attention. Contradiction should challenge the producing focuses and open an alternative View.

## Rejected View ledger

A rejected View is compacted into:

- its signature;
- context fingerprint;
- attention anchors;
- qualified verdict;
- rejection reasons;
- violated constraints and contradictions;
- reusable discriminators;
- explicit revisit conditions.

The same View is blocked in the same context until a relevant condition or semantic fingerprint changes. Its underlying memory remains intact.

## Link plasticity

Memory links accumulate evidence by independence key. Repeated independent support can move a link from candidate to supported and verified. Strong contradiction can dispute it.

## Capsule refinement

Repeated outcomes can produce:

```text
reinforce
narrow
extend
split
dispute
supersede
retain raw trace
```

Mixed outcomes with discriminators improve the capsule boundary instead of merely averaging confidence.
